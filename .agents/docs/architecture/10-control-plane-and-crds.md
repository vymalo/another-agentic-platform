#### D2

> **`aap-domain`** ([README](../../../crates/domain/README.md#references-and-the-default-image-slice-d2-ad-029)): `resolve` and `validate` take an `Externals` (the `ModelEndpoint` and `ToolProvider` objects the config names, by name, and the operator's default image) and **read the references into the config before anything else**, so the rest is the code that reads an inline one: an endpoint with the address and key of an inline model gives the same variables, the same MCP file, the same pods and the same digest (`tests/references.rs` compares whole resolved agents, on both examples, on the §60a example and on every `optional` case).
>
> **After review, four more rules:** an issue never carries a URL whole (it reaches the status and the Events of every service that uses the object): a refused URL is shown as its scheme and host, `***` for a user name and password and `/…` for the rest (`shown_url`); a reference's name, and `configRef`'s, must be a DNS-1123 subdomain, or the service is `ConfigInvalid` naming the field before any request is made with it (the CRD asks for one character only, and a name goes into the path of the GET: `bad name` failed the pass for good and `x?watch=true` added a query; not a CRD pattern, which would tighten `configRef`); an MCP server's name is adam-rs's `server_name_ok` (at most 64 characters, no `__`, not ending in `_`: *verified 2026-10-15* by `git show` at `0391809`, identical at `9a1fd4e`, **not run**), because the loader refuses the file of a server named otherwise at every start; and a service blocked by a missing referent (not by an invalid config) is read again in the `pending` period, 15 s, not the settled 5 minutes, because the two objects of a config are applied one request at a time.
>
> **The two watches are isolated from the services' own triggers**: kube's `Controller` puts one backoff around all of its triggers, so a kind whose CRD is not installed (or that the `Role` cannot list) would have delayed every service by a backoff's length, thirty seconds and more (*measured 2026-10-15* on the fake, in virtual time: 11 to 16 s for a service that existed at start, 27 to 42 s for one created later); each watch has its own backoff, logs and drops its errors, and finds its kind when the CRD appears.
>
> **The chart** ([README](../../../deploy/operator/README.md#the-default-agent-image)): `Role` gains `get`, `list` and `watch` on `modelendpoints` and `toolproviders` and no write; `defaultAgentImage` is rendered as `DEFAULT_AGENT_IMAGE` and ships the coder image `sha-9a1fd4e` by tag and digest (`sha256:c3c178b7…12b44`, *verified 2026-10-15*, anonymous manifest request to ghcr.io, HTTP 200), the one the kind end-to-end of the coder runs; the chart refuses a value without a tag and a digest, and `latest`. Proven by `cargo test`: the parity goldens and the pinned digest of the inline examples **did not move**; the domain's table tests (22 new cases in `tests/references.rs`, and the invalid examples of the shared kinds now asked of `validate`); the reconciler on the `Memory` ports and the fake API server (a referent created after the config unblocks it, an edit rolls the digest and a title does not, a deletion blocks naming it and the pod spec is what ran, the default image and its bump); the running operator against the fake's list and watch (change, deletion and creation of either kind reconcile the right services, an object nobody references reconciles none); `render-check.sh` (the Role line by line, the variable, the refusals) and `bump-tag-test.sh` (the bump leaves `defaultAgentImage` alone). **Each property was broken on purpose and a named test failed** (the resolution equivalence in three ways, the referent validation in four, the `optional` rule in three, the default-image rules in three, the watch mapping in five). **The new case of `bin/operator/tests/cluster.rs` was run by hand against a bare kube-apiserver v1.35.8 and etcd on 2026-10-15** with the test playing the controller manager, with the other twelve: 13 of 13 passed; and, after the review, a case that deletes the two shared CRDs (run alone, `AAP_TEST_DROP_SHARED_CRDS=1`) passed against a new bare kube-apiserver: a plain service is `Ready` and follows its config, a service that references the kinds says they are not installed, and it goes `Ready` once the CRDs and the objects are there (`AlwaysAllow` authorisation: it proves the reads, the watches, the digest and the block against a real API server, and nothing of the `Role`).

> - **`ToolProvider.mcp.tools` is mapped, not refused.** adam-rs supports a per-server `tools` allow-list in the file `ADAM_EXTRA_MCP_FILE` names, which the operator writes (*verified 2026-10-15*, read with `git show` at `0391809`, the revision of the parity goldens, **not run**; and **kept at `9a1fd4e`**, the revision of the coder image the chart ships, *verified 2026-10-15* with `git show` and `git grep` there, **not run**: four of the five files below are byte-identical at both revisions (`git diff --stat 0391809 9a1fd4e` over them is empty), `raw.tools` is read in `crates/adam-agent-fs/src/load/mcp.rs` and `"tools": ["echo"]` is in `crates/adam-assembly/tests/extra_mcp.rs`, which asserts `the allow-list applies`; `bin/adam-agent/README.md` changed elsewhere (a hardening bullet, the log filter) and its `ADAM_EXTRA_MCP_FILE` row, line 174 at `9a1fd4e`, still says "Same parser, `${VAR}`, `tools`, `optional` and policy as `mcp.json`"): `crates/adam-agent-fs/src/schema/mcp.rs` (`tools: Option<Vec<String>>`, "the allow-list of tools (an adam extension); `None` allows all"), `crates/adam-agent-fs/src/load/mcp.rs` (each entry must become `<server>__<tool>`: not empty, not starting with `_`, ASCII letters, digits, `-` and `_`, the name at most 64 characters), `bin/adam-agent/README.md` ("same parser, `${VAR}`, `tools`, `optional` and policy as `mcp.json`"), `deploy/coder/templates/_helpers.tpl` (`coder.extraMcpJson` writes `tools` when the list is not empty) and `crates/adam-assembly/tests/extra_mcp.rs` (the allow-list applies to the extra file's server).

#### D3

#### D4

The `AgentObjects` tests also run the suites against stores with a fault (a stale token accepted, a GitOps object written, a referenced object deleted, no label, a value in an offer) and authenticators with one (unavailable keys called invalid, a token in an error), and require the suites to fail. **Each property was broken on purpose and named tests failed**: a round-trip field dropped (`every_form_round_trips` and seven more for `description`; `a_form_with_every_optional_field_set_round_trips` and the property for `createRepoOwners`; the model endpoint's `models`), a literal credential added to the objects (`the_objects_hold_only_what_they_were_given` among four), the annotation a tool writes kept in the export (four tests, the golden among them), a secret slot that accepts an unknown member (two), the offered-key check off (four), the memory store accepting a write over a GitOps agent or shared object (`a_gitops_agent_is_read_and_never_written`, `a_gitops_config_blocks_the_create_of_its_name`, `a_gitops_shared_object_is_read_and_never_written`), accepting a stale token (`a_stale_token_is_refused_and_nothing_changes`; on a shared object `shared_objects_have_the_same_life`), deleting a referenced model or tool server (`a_shared_object_that_agents_name_is_not_deleted` and `a_shared_object_nobody_names_is_deleted`), the `ETag` that ignores the config (three), the ownership rule that ignores Argo CD's annotation (five), an offer that lists the key without the label, unavailable keys called invalid, the re-render of the config left out of `load_agent` (five), the check for a member the types do not know left out (two), and the deployment part read from the defaults and not from the objects (eleven).
